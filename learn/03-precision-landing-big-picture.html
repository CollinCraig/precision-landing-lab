Precision landing: the big picture

The camera finds the tag. Your code turns the detection into a target estimate. A LANDING_TARGET message carries the estimate to ArduPilot. ArduPilot steers the descent. This page explains each step at concept level.

Time ~25 minPrepares estimate.py and safety.py (M3)Numbers all illustrative unless a source is given
A

The pipeline

ArduPilot does the steering. Your code gives it a good measurement of where the pad is. ArduPilot combines the measurement with its own motion data and flies the aircraft down.

To use this path, set PLND_ENABLED to 1 and PLND_TYPE to 1 (MAVLink). Other PLND_TYPE values select IR-LOCK, a Gazebo source or a SITL source. Precision landing works in LAND mode and in the final stage of RTL.

The source field of the TargetEstimate matters. In camera mode, no estimate can come from simulator truth. The Rust validator checks this rule.

B

Rate

The ArduPilot docs ask for "no less than 2hz". A higher rate is better.

A message is not a command

LANDING_TARGET gets no ACK. It is a measurement. ArduPilot uses it while it is fresh. If the messages stop, ArduPilot treats the target as lost.

Frames again

In BODY_FRD, the numbers turn with the drone. ArduPilot knows its attitude, so it can correct for the turn. Page 02 shows why this matters.

C

ArduPilot's estimator

Two choices: PLND_EST_TYPE

0, RawSensor. ArduPilot uses each measurement as it arrives. Noise in the measurement goes directly into the steering.

1, KalmanFilter. ArduPilot predicts the target position from its own accelerometers. Then it corrects the prediction with each camera measurement. The result is usually smoother.

Tuning ideas (names only)

PLND_ACC_P_NSE sets the accelerometer noise in the filter. The docs say: "higher values weight the input from the camera more".

PLND_LAG tells ArduPilot how old a measurement is when it arrives (0.02 to 0.25 s). Camera processing adds delay, so this value matters.

PLND_XY_DIST_MAX stops the descent while the target is too far to the side.

D

When the target is lost

The documented behaviour

PLND_TIMEOUT (0 to 20 s): the vehicle continues to descend for this time after the target is lost. Then it acts on PLND_STRICT.

PLND_STRICT: 0 lands vertically (not strict). 1 retries the landing. 2 does not land and hovers (very strict).

PLND_RET_MAX (0 to 10) limits the number of retries. PLND_RET_BEHAVE selects where a retry goes: to the last location where the camera saw the target (0), or toward the approximate target location (1).

PLND_ALT_MIN (0 to 5 m): below this height, the vehicle continues to land vertically, even if the target is lost. PLND_ALT_MAX (0 to 50 m): if the vehicle does not find the target, it descends vertically down to this height. Both need a rangefinder.

Your layer is separate

ArduPilot's rules handle a lost target inside LAND mode. Your M3 safety.py is a separate layer with its own abort and go-around decisions. This page does not design that layer.

What the toy does

Each run starts 6 m up with a random side offset. The toy descends at 0.5 m/s and steers toward its estimate of the pad.

Each camera frame adds random error with the selected σ. "Filtered" smooths the measurements. "Raw" uses each one directly.

Below the "target lost" height, no measurements arrive. The toy continues down with its last estimate. Gusts push it away, and nothing corrects the push.

Things to see

Raise the noise with "raw". Then select "filtered". Set gusts off and move "target lost". Then set gusts strong. The loss alone does little. Loss plus a disturbance grows the spread.

The dashed circle is the charter goal: 25 cm in 8 of 10 calm landings.

F

Check yourself

1. Your code sends LANDING_TARGET at 1 Hz. What do the ArduPilot docs ask for?
No less than 2 Hz, and a higher rate is better.
2. Which field tells ArduPilot to use x, y, z instead of the two angles?
position_valid = 1.
3. With PLND_STRICT = 2, the target disappears at 4 m. What happens after the timeout?
The vehicle does not land. It hovers. (Very strict.) Retries up to PLND_RET_MAX come first.
4. The target disappears at 0.5 m, and PLND_ALT_MIN is 1 m. What happens?
The vehicle continues to land vertically. Below PLND_ALT_MIN, a loss does not cause a retry. This needs a rangefinder.
5. In the toy, why does "target lost" do little when gusts are off?
Without a disturbance, nothing pushes the aircraft away from its last good estimate. Real flights always have some disturbance and some drift. So the loss height matters in real flights.
6. Why must a camera-mode run never read simulator truth?
Truth makes the perception look perfect. The result then says nothing about the real pipeline. The validator rejects such a run.

This page explains concepts only. It contains no AprilTag pose code, no frame conversion code and no abort or go-around logic. The toy model in section E is a JavaScript sketch for intuition. It is not a design for estimate.py or safety.py.
