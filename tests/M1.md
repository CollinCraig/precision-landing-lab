# M1 test groups

Run these commands from the platform root. Use the existing Python environment.
The commands do not install packages or start a container.

## Platform checks

```sh
python -m unittest discover -s tests -p test_m1_infrastructure.py -v
python -m unittest discover -s tests -p test_pilot_api.py -v
python -m unittest discover -s tests -p test_learn_cli.py -v
python -m unittest discover -s tests -p test_runner.py -v
python -m unittest discover -s tests -p test_power.py -v
```

These checks must pass before you interpret pilot failures.
A platform failure is not an expected exercise failure.
No platform check contains a mission or sends flight commands.

## Pilot step checks

The owner's code is in a separate repository (`landing-pilot`). Do not copy it here.
Use the learning tool. It sets `M1_PILOT` and keeps the last run in the pilot folder.

```sh
scripts/learn --pilot <pilot folder> step 1
scripts/learn --pilot <pilot folder> status
```

The pilot repository has a wrapper: `./learn step 1`.
The empty starter code fails all 12 tests. These failures are intentional.
Each test class is one step:

| Step | States | Tests |
|---|---|---|
| 1 | CONNECT, WAIT_READY | success path, no heartbeat, never ready |
| 2 | SET_GUIDED, ARM | success path, mode stuck, ACK accepted but not armed, arm refused |
| 3 | TAKEOFF, CLIMB, HOLD | success path, climb stuck, telemetry stops |
| 4 | LAND, WAIT_DISARM | complete mission, disarm never arrives |

An exception, a missing outcome or a runner time-limit failure does not satisfy a bounded failure test.
Fake tests use synthetic provenance and temporary evidence folders.

Do not use full test discovery as a platform verdict. Full discovery also runs the pilot step tests when `M1_PILOT` is set.

## Optional SITL integration

```sh
M1_PILOT=<pilot folder> python -m unittest discover -s tests -p test_m1_sitl.py -v
```

This command skips the integration test by default.
Do not enable it until the owner approves the run and `scripts/sitl-up` runs SITL.
The integration test does not start, install or stop SITL.

Before an approved run:

1. Set `M1_PILOT` to the pilot folder.
2. Set `M1_SITL_ENDPOINT` to the existing simulation endpoint.
3. Set `M1_ARDUPILOT_VERSION` to the actual connected build.
4. Set `M1_CONTAINER` to the actual image name and SHA256 digest.
5. Set `M1_RUN_ROOT` to `$LAB_HOME/local/m1/runs`.
6. Set `M1_RUN_ID` to a new run identifier.
7. Set `M1_RUN_SITL=1` for the integration command.

The CLI keeps the wall-power guard and records actual Git provenance. It uses the `sitl` time budgets and a 240 s timeout.
The test checks phase order, hold time and recorded telemetry.
Declared events alone do not prove aircraft behaviour.
The integration test is an acceptance check, not proof of real-aircraft safety.
Keep raw run evidence in `local/`. Do not commit it.
