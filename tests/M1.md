# M1 test groups

Run these commands from the worktree root. Use the existing Python environment.
The commands do not install packages or start a container.

## Infrastructure checks

```sh
python -m unittest discover -s tests -p test_m1_infrastructure.py -v
python -m unittest discover -s tests -p test_runner.py -v
python -m unittest discover -s tests -p test_power.py -v
```

These checks must pass before you interpret learner failures.
An infrastructure failure is not an expected exercise failure.
The protocol check launches a child process but sends no flight commands.

## Learner checks

```sh
python -m unittest discover -s tests -p test_m1_learner.py -v
```

The empty exercise fails all eight tests. These failures are intentional and do not use expected-failure decorators.
The completed exercise must pass all eight tests.
One test checks the successful sequence. Seven tests remove required state confirmations or telemetry.
An exception, missing outcome or global watchdog failure does not satisfy a bounded learner failure.
Fake tests use synthetic provenance and temporary evidence directories.

Do not use full test discovery as an infrastructure verdict. Full discovery also includes the incomplete learner exercise.

## Optional SITL integration

```sh
python -m unittest discover -s tests -p test_m1_sitl.py -v
```

This command skips the integration test by default.
Do not enable it until the owner approves the run and supplies an existing simulation endpoint.
The integration test does not start, install or stop SITL.

Before an approved run:

1. Set `M1_SITL_ENDPOINT` to the existing simulation endpoint.
2. Set `M1_ARDUPILOT_VERSION` to the actual connected build.
3. Set `M1_CONTAINER` to the actual image name and SHA256 digest.
4. Set `M1_RUN_ROOT` to `$LAB_HOME/local/m1/runs`.
5. Set `M1_RUN_ID` to a new run identifier.
6. Set `M1_RUN_SITL=1` for the integration command.

The CLI preserves the wall-power guard and records actual Git provenance.
The test checks phase order, hold time and recorded telemetry.
Declared events alone do not prove aircraft behaviour.
The integration test is an acceptance check, not proof of real-aircraft safety.
Keep raw run evidence in `local/`. Do not commit it.
